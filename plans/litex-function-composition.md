# 函数复合：`compose(f,g)` 与 `f ∘ g`

日期：2026-10-18。状态：**设计提案，尚未实现**。接续 [Phase 1](litex-latex-phase-1.md) 的 P5；本文件替代其中旧的一元复合草案。用户已决定不增加原生 `restrict`，限制函数继续使用现有匿名函数。

## 1. 推荐接口与主例子

两个写法构造同一个函数对象，左边是外层，右边是内层：

```text
compose(f,g) = f ∘ g
(f ∘ g)(x) = f(g(x))
(f ∘ g)(x,y) = f(g(x,y))
```

以下是拟议验收程序，不是当前内核已经支持的代码：

```text
have fn square(t R) R = t^2
have fn gap(x, y R: x < y) R = y - x

have h fn(x, y R: x < y) R = square ∘ gap
h(1,3) = 4
compose(square,gap)(1,3) = 4
(square ∘ gap)(1,3) = square(gap(1,3))

# 应拒绝：违反 gap 的原始条件，不因 square 能接收负数而合法。
h(3,1) = 4
```

现有匿名函数可表达同一构造：`fn(x, y R: x < y) R {square(gap(x,y))}`。原生复合的收益是省去重写参数和条件，并提供稳定的对象、数学规则和 `\circ` 输出；它不会增加一种新的函数定义域模型。

**推荐第一版支持：外层恰好一个参数，内层任意固定的正参数个数；保留内层全部条件。** 这样覆盖用户提出的 `fn(x, y R: x < y) ...`，也不需要隐式元组拆包或新的限制语法。

## 3. 数学契约与良定义检查

用数学简写描述签名，`P`、`Q` 是现有可表达的有序条件列表：

```text
g : fn(x1 A1, ..., xn An: P(x1,...,xn)) B     n >= 1
f : fn(t D: Q(t)) C

compose(f,g) : fn(x1 A1, ..., xn An: P(x1,...,xn)) C
compose(f,g)(x1,...,xn) = f(g(x1,...,xn))
```

构造时依次要求：

1. `f`、`g` 各自良定义，而且有带来源证明的完整可调用签名；`f` 的这个调用层是一元。
2. 在新局部作用域中，按 `g` 的顺序引入参数、载体和条件。用原有检查器验证 `g(x1,...,xn)`。
3. 在同一作用域证明这个值属于 `D` 并满足 `Q`，再检查 `f(g(...))` 及其属于 `C` 的证据。
4. 返回函数的完整定义域就是 `g` 的完整定义域。返回集合取经过检查的外层返回上界 `C`。

### 精确的数学判据

用 `D_g` 表示包含全部载体和条件的合法输入赋值集合，`D_f` 表示外层的完整一元输入域；这两个名字只是数学记号，不新增 `dom` 对象。对已良定义、调用形状合适的 `f,g`：

```text
compose(f,g) 可构造  iff  fn_range(g) subset D_f

等价的逐点义务：
forall x1 in A1, ..., xn in An:
    P(x1,...,xn)
    => g(x1,...,xn) in D 且 Q(g(x1,...,xn))
```

这是数学上的判据，不是要求实现先生成 `fn_range` 再枚举它。`g` 的完整域与它的声明载体要区分，`g` 的实际值域与它的返回上界 `B` 也要区分。只需实际值域落在外层完整域；不要求外层定义域等于内层声明返回集合。

若能从签名证明 `B subset D`，且对所有 `t in B` 有 `Q(t)`，这是足够的快速路径。若不能，仍可在 `g` 的参数/条件下直接证明输出的相应事实。这两条路径证明同一个判据，不能变成两种不同的复合语义。

### 构造 WD 与调用 WD 分开

推荐构造时复用已有匿名函数检查，不另外复制一套 binder/guard 验证逻辑：

1. 检查两个操作数及真实签名来源，确认外层一元。签名选择不能依赖尚未引入的内层形式参数。
2. 为内层参数分配不捕获外部变量的新 binder，保持顺序、载体与条件；返回上界取已检查的外层返回集合。
3. 内部建立已有的匿名函数形状 `fn(args: P) C {f(g(args))}`，走现有匿名函数 WD。该过程检查参数载体、条件自身 WD、返回集合 WD、函数体 WD 及返回成员关系；空域的特殊处理也沿用现有证据规则。
4. 局部环境中只假设内层的 `P`；外层的 `Q(g(args))` 要逐条证明。绝不能把它追加到复合函数的参数条件中，也不能用还未成立的复合成员关系证明自己。
5. 保留签名来源、binder 对应关系和匿名函数的完整成功证据（含其 `local_env`），将它作为 Composition 的定义证据，再经现有存储路径提供可调用接口。保留已有子证明即可，不必重复抄写一份证据树或新增全局缓存。

对后续 `(f ∘ g)(a1,...,an)`，只增加这次实参的义务：各 `ai` 良定义、属于相应 `Ai`，并满足 `P(a1,...,an)`。随后实例化已保存的构造证明，得到 `g(a1,...,an)` 与 `f(g(a1,...,an))` 的合法性。不要每调用一次就重新搜索一次全称兼容性证明。

完整例子（拟议验收，未运行）：

```text
have fn gap(x, y R: x < y) R = y-x
have fn inv(t R: t != 0) R = 1/t
let h = inv ∘ gap

# 构造阶段：在任意 x,y in R 且 x<y 下证明：
# gap(x,y) in R；gap(x,y)=y-x；y-x>0；gap(x,y)!=0。
# 因此返回签名是 fn(x,y R: x<y) R。

h(1,3) = 1/2       # 调用只需要 1,3 in R 和 1<3。
h(3,1) = -1/2      # 拒绝；内层完整域不包含这组输入。
```

这个构造不会重新证明任意函数是函数：`f,g` 已有的成员/定义证据提供存在性和唯一值；匿名函数构造给出复合图，完整域上的函数外延性保证该定义唯一。不增加“复合存在”的用户公理或独立存在性选择接口。

### 失败意味着什么

检查器必须区分来源/形状失败与尚未证明的条件。`compose(123,g)` 没有合适的外层可调用接口；`inv ∘ identity_R` 的全称非零条件确实不成立；抽象 `g` 尚未提供非零证明，则只能报告未证义务，不能断言实际存在零点。

建议诊断展示：当前构造、内层局部假设、失败的外层载体/条件及其来源。例如 `inv ∘ g` 缺少证据时，展示待证的 `forall x R: g(x) != 0`。作者可以证明该事实后重试，不需要改写 `compose`。有界验证不承诺自动证明任意真的全称命题；对空域也不无证跳过既有子对象与函数体 WD 检查。

不要求语法上 `B = D`，也不把 `B subset D` 当作唯一入口：内层的实际输出可能比声明上界小。例如下列拟议构造应可用已有定义展开或显式事实完成检查：

```text
have fn inv(t R: t != 0) R = 1/t
have fn one(x R) R = 1
have good fn(x R) R = inv ∘ one
good(0) = 1
```

对抽象 `g : fn(x R) R`，作者可以先提供 `forall x R: g(x) != 0`，再构造 `inv ∘ g`。有这条已验证事实才有相应保证；验证器不负责无界搜索任意函数的不为零证明。

相反，以下构造必须拒绝，尽管它在很多单点上可以计算：

```text
have fn identity(x R) R = x
inv ∘ identity
# 失败义务：对每个 x in R 都有 x != 0。

fn(x R: x != 0) R {inv(identity(x))}
# 作者显式选择较小定义域时，使用已有匿名函数。
```

另一种数学选择是部分函数图复合，自动取 `g` 的定义域中满足外层载体及 `Q(g(x))` 的部分。它的优势是对任意两个一元函数图都可构造，函数图复合的结合律也无需整个中间值域相容。例如 `inv ∘ identity_R` 会自动得到定义在非零实数上的函数，`inv ∘ zero_R` 会得到空函数。本提案仍推荐保留内层完整域的严格复合：它与显式匿名函数接口一致，在构造时暴露域不相容；代价是不能承诺任意一侧嵌套合法就允许重新加括号。两种语义都是数学上可行的选择，但切换会改变已发布函数的域、WD 时机和等式，不能以后作为无行为变化的重构。最终实现前需由用户确定，当前记录为推荐方案。

### 多个签名、别名与空域

- 候选必须来自现有的已检查构造或精确对象成员事实。候选来源、等式路径和使用的 FactId 均保留；不能只调用返回第一个 `FnSet` 的结构读取器就宣称良定义。
- 同一个函数可以有多个返回上界。只要检查成立，不能因为后来增加一个返回成员事实就改变复合的函数图；也不能把多个候选的输入域合并或取交集。
- 参数个数和完整定义域沿用选中的真实签名。替换签名需要已有完整定义域等价证据；不能证明等价的不同调用形状不自动互换，作者用显式 `fn` 指定接口。
- 别名按现有权限处理。例如 `have alias fn(x R) R = f` 提供明确接口；`let alias = f` 不获得读取任意等号邻居签名的新权限。`let h = compose(f,g)` 自身则需要保留这个已检查构造的可调用证据。
- 空输入域仍须检查两个子对象及外层一元可调用性。沿用匿名函数现有的空域和函数体 WD 约束；不能让 `compose(123,empty_fn)` 因空域而通过。

## 4. 参数边界

| 形式 | 推荐行为 |
| --- | --- |
| `f` 一元，`g` 二元/多元且带条件 | 支持；`(f ∘ g)(x,y)=f(g(x,y))`，完整继承 `g` 的参数与条件。 |
| `g(x)` 返回一个元组，`f(p cart(A,B)) C` | 支持，把元组作为一个参数。 |
| `g(x)` 返回元组，`f(a A,b B) C` | 不自动拆包；作者写 `fn(x X) C {f(g(x)(1),g(x)(2))}`，遵守现有从 1 开始的元组调用接口。 |
| `g` 返回函数 | 一次复合使用 `g` 的第一层结果。若 `f` 接受该函数，合法；不会自动寻找更深一层的标量。 |
| `f(g(x,y))` 的结果还是函数 | 保留结果的签名，后续 `(f ∘ g)(x,y)(z)` 按现有多层调用检查。 |
| 外层多元、自动柯里化、逐坐标复合 | 第一版不支持。`fn(x,y A) C {f(g(x),g(y))}` 已表达作者明确选择的组合。 |
| `fn()` 零元函数 | 不增加支持；现有解析要求至少一个参数。 |
| 裸内置运算名 `sin`、`exp` | 本次不把它们提升为函数值；使用 `(fn(t R) R {sin(t)}) ∘ g`。 |

表中的例子说明拟议边界，不是本次运行结果。参数载体允许引用外层已存在的对象，但不能引用本签名的参数。不要为了复合顺便放开依赖载体/返回类型。

## 5. `∘` 的语法、优先级与输出

使用 **U+2218 RING OPERATOR `∘`**。`f∘g` 和 `f ∘ g` 都可输入；不把字母 `o`、度数符号 `°`、中点 `·` 当作别名。不增加裸 `\circ` 的 LaTeX 源码输入支持。

建议在当前 `parse_closed_range` 与 `parse_unary` 之间加入右结合的 `parse_compose`。因此调用、字段、阶乘、乘方以及现有一元负号的组合规则优先于复合；复合优先于 `...`、乘除、加减、笛卡尔积、交并。不改变既有运算符之间的优先级。

| 输入 | 解析结果/边界 |
| --- | --- |
| `f ∘ g ∘ h` | `compose(f,compose(g,h))`，右结合。 |
| `(f ∘ g) ∘ h` | `compose(compose(f,g),h)`，保留不同树形。 |
| `(f ∘ g)(x)` | `compose(f,g)(x)`。 |
| `f ∘ g(x)` | `compose(f,g(x))`；先算 `g(x)`，它必须是合适的函数值。这不等于 `f(g(x))`。 |
| `f ∘ g + h` | `(f ∘ g) + h`；解析有确定结果，但不因此新增函数加法。 |
| `f ∘ g^2` | `f ∘ (g^2)`；乘方自身仍要通过现有 WD。 |
| `f ∘`、`∘ g`、`compose(f)`、`compose(f,g,h)` | 精确位置报缺少操作数/参数个数错误。 |

词法层必须保留 UTF-8 源位置，包括没有空格的输入。中缀不是简单 token 替换：两个方向都直接构造相同的 Composition AST。

推荐规范文本/IR 仍输出 `compose(f,g)`，便于稳定序列化和保留树形；LaTeX 输出 `f \circ g`。作为调用头时输出 `(f \circ g)(x)`；显式左嵌套必须输出括号。不能以结合律为由抹掉括号，因为某一种分组可能尚未良定义。

## 6. Obj 与证明责任

### 具体 AST 提案（等待后续实现授权）

只增加一个函数对象变体及两个字段的负载：

```rust
// 新增到现有 FunctionSpace：
Composition(Composition),

pub struct Composition {
    pub outer: Box<Obj>,
    pub inner: Box<Obj>,
}
```

`compose(f,g)` 和 `f ∘ g` 都对应 `outer=f, inner=g`。对象持有函数值，不持有复制的声明、参数列表、选择后的签名、缓存或证明。无需更改 `FnSet`、`AnonymousFn`、`FnObjHead`、`Stmt`、`Fact` 或 `Identifier` 的现有字段。此处是明确的结构提案，不是本次已经获准的内核编辑。

纯解析展开 `f ∘ g` 为 `fn(...) {...}` 的问题是：参数个数、条件和返回集合来自经过检查的函数接口，解析阶段不能猜；展开还会丢失复合对象的规则与输出身份。采用独立对象，检查后的匿名函数形状只作为定义解释/证明构造。

### WD 和调用证据

成功证据按实际阶段组织，至少保留：两个子对象 WD、内外层完整签名及来源、局部参数引入和条件假设、内部调用 WD、外层输入义务及调用 WD、结果所属返回集合、派生的完整签名，以及 `local_env: Box<ExecEnv>`。具体结果类型应镜像已有 FunctionSpace 分派结构，顺序阶段用 struct，失败定位到真实阶段。

派生签名和局部 binder ID 只能随保留的作用域证据流动。不能把已丢弃候选作用域中的 WD ID 或 FactId 发布到外层。重命名、实例化和比较覆盖两个操作数，并有外部变量捕获控制。

可调用接入至少覆盖：

1. 直接调用 `(f ∘ g)(args)`，通过已有 `FnObjHead::Object`。
2. 存储后的 `have h fn(...) C = f ∘ g` 与 `let h = f ∘ g`。
3. 嵌套复合、被返回的复合、字段/模板中的已检查函数值。
4. 函数空间成员关系、完整定义域读取、`fn_range`、`preimage` 与已有函数消费者。

`function_domain.rs` 需要能从已检查 Composition 得到完整域证明；函数应用 WD 需要携带相应证据；定义展开消费父调用证据。先完成这条链，不能只让第一行构造成功。返回集合是上界，不要把某次证据选择写进对象的语法身份。

**不提议新增 Env/Runtime 字段、签名注册表、缓存策略、事务规则或搜索权限。** 优先扩展现有构造证据分派。若实现确实需要改变这些状态契约，另列具体结构变化；不能借本提案默许。

## 7. 定义关系与 BT rules

所有规则首先要求目标涉及的对象和调用良定义。下表是拟议规则，不是当前功能清单。

### 第一轮必须完成

| 关系 | 前提与责任 |
| --- | --- |
| `(f ∘ g)(args) = f(g(args))` | args 满足 `g` 的完整域；消费父调用与构造证据，归入函数定义展开，不重复猜签名。 |
| `f ∘ g = fn(args: P) C {f(g(args))}` | 右侧显式签名与构造的完整域匹配；通过定义/函数相等路线，不全局双向重写。 |
| `f ∘ (g ∘ h) = (f ∘ g) ∘ h` | 相邻复合 `f ∘ g`、`g ∘ h` 兼容即可推出两边 WD 与相等；普通链中 `f,g` 一元，`h` 可多元。保留两个中间构造证据，不借等式循环证明 WD。 |
| `id_B ∘ g = g` | `id_B = fn(t B) B {t}`，`B` 包含所有合法 `g` 的输出；`g` 可多元。 |
| `f ∘ id_D = f` | `f` 一元；`id_D` 的完整域必须与 `f` 相同，包括条件。`fn(x A: P(x)) A {x}` 可作有条件的恒等函数。 |
| `fn_range(f ∘ g) $subset fn_range(f)` | 使用已检查复合及两侧 image 证据；不擅自升级为集合相等。 |
| 替换相等的操作数 | 复用已有带证明的等式合同替换；`f1=f2` 不能仅凭名字或函数体文本匹配。 |

恒等函数是已有匿名函数，不新增 `id` 内置名字。对于多元 `g`，左单位律仍适用；`g ∘ id` 的外层不再一元，不能直接宣称右单位律适用。需要元组化时由作者显式构造适配函数。

### 应当由接口直接保证的性质

**函数空间封闭性也是核心性质，不只是辅助类型推断。** 例如下面是期望契约；签名中条件只是数学简写：

```text
g in fn(x,y A: P(x,y)) B
f in fn(t B) C
=> compose(f,g) in fn(x,y A: P(x,y)) C
```

`P` 不丢失；无需证明 `g` 满射到 `B`。若外层带条件，则额外证明对所有内层合法输入成立的外层条件。改变返回上界、binder 名称或使用等价的完整域表示，都不能改变复合图。

**结合律要能从相邻兼容性推出合法性，不只在最终等式处加一句“假设两边 WD”。** 用 `Compat(f,g)` 作为上文值域包含判据的数学缩写（不新增 prop）：

```text
Compat(f,g) 且 Compat(g,h)
=> Compat(compose(f,g),h)
=> Compat(f,compose(g,h))
=> compose(compose(f,g),h) = compose(f,compose(g,h))
```

这里两个新兼容性都独立从最初两个前提推出：`h(x)` 合法进入 `g`，再由 `g` 的每个合法输出都能进入 `f` 完成逐点证明；不使用尚未验证的结合律。在常见的 `h:A→B, g:B→C, f:C→D` 接口链上，这些前提由已有签名给出，作者不应额外手写两个嵌套复合的 WD 证明。

**相等与逐点相等要分开。** 一般合同替换是 `f1=f2, g1=g2 => f1∘g1=f2∘g2`；也应能通过现有外延性显式证明更精确的性质：

```text
# 两个复合已良定义，内层均为同一个 g：
forall y in fn_range(g): f1(y)=f2(y)
=> f1 ∘ g = f2 ∘ g
```

`f1,f2` 可以在别处不同，甚至完整域不同，只要都接受 `g` 的全部输出。反过来，在 `g` 的一部分输入上相等不足以证明两个复合函数图相等。

严格复合的结合律不能反过来替未检查对象提供良定义证明。关键反例：

```text
have fn inv(x R: x != 0) R = 1/x
have fn identity(x R) R = x
have fn one(x R) R = 1

inv ∘ (identity ∘ one)      # 合法，最内层总返回 1。
(inv ∘ identity) ∘ one      # 非法，inv ∘ identity 并非全域合法。
```

这也说明右结合是会影响可接受程序的公开选择，不能在 alpha-normalization 或解析时使用无条件结合律。

### 第二轮关系扩展

第一轮完整交付后再接入，不能把这些勾成已实现：

```text
preimage(f ∘ g,z) = preimage_set(g,preimage(f,z))
preimage_set(f ∘ g,S) = preimage_set(g,preimage_set(f,S))

# 以下限定现有一元映射谓词，A/B/C 是对应的完整接口：
$injective(A,B,g), $injective(B,C,f) => $injective(A,C,f ∘ g)
$surjective(A,B,g), $surjective(B,C,f) => $surjective(A,C,f ∘ g)
$bijective(A,B,g), $bijective(B,C,f) => $bijective(A,C,f ∘ g)
```

原像规则延续现有多元输入赋值的元组表示，不改变 arity。映射谓词组合需要真实的相同中间接口，不能只看到两个 `$injective` 名称就套用。消去律和已有函数间的逆映射关系在下面列出准确范围；选出的逆函数对象、导数链式法则仍留在对应接口后续规划。

### 映射性质、消去律与逆映射关系的准确范围

这些都是需要能够显式验证的数学性质；是否再为其增加自动 BT 是独立的交付选择。以下除特别说明外固定一元接口 `g:A→B`、`f:B→C`，每个箭头包含完整输入域和已验证返回成员关系，不要求返回上界恰好等于实际值域。

| 性质 | 准确结论与条件 | 建议验证方式 |
| --- | --- | --- |
| 单射复合 | `g`、`f` 单射，则 `f∘g` 单射。 | 展开复合值等式，先用 `f` 单射，再用 `g` 单射；复用现有 `$injective` 定义。 |
| 满射复合 | `g` 满射到整个 `B`，`f` 满射到 `C`，则 `f∘g` 满射到 `C`。 | 对 `c in C` 先取 `f(b)=c`，再取 `g(a)=b`；保存两次原像证据。 |
| 双射复合 | `g`、`f` 双射，则 `f∘g` 双射。 | 使用前两条及现有 `$bijective` 定义，不新增第三套推理。 |
| 有效的逆向推论 | `f∘g` 单射 ⇒ `g` 单射；`f∘g` 满射到 `C` ⇒ `f` 满射到 `C`。 | 用应用定义、已知等式/原像；不能推出 `f` 单射或 `g` 满射。 |
| 左消去 | `g1,g2:A→B`，`f:B→C` 单射，且 `f∘g1=f∘g2` ⇒ `g1=g2`。 | 对每个合法输入取值，再使用单射和完整域外延性。仅证明 `g1,g2` 单射不够。 |
| 右消去 | `g:A→B` 满射，`f1,f2:B→C`，且 `f1∘g=f2∘g` ⇒ `f1=f2`。 | 用 `g` 覆盖每个 `b in B`，再用外延性。仅有 `g` 单射或像集包含于 `B` 不够。 |
| 像集相等 | 若 `g` 满射到外层完整域 `B`，则 `fn_range(f∘g)=fn_range(f)`。 | 一般只有包含；反向包含使用 `g` 的满射原像。 |
| 左逆/右逆 | 对 `k:B→A`，`k∘g=id_A` ⇒ `g` 单射；`g∘k=id_B` ⇒ `g` 满射。两式同时成立时互为逆映射。 | 不需要先发明 `inverse(g)` 对象；已有函数值与恒等等式即可表达。 |
| 逆的顺序 | 若 `u:B→A` 与 `g` 互逆、`v:C→B` 与 `f` 互逆，则 `u∘v` 与 `f∘g` 互逆。 | 由已合法的结合律和单位律推导，次序倒转；不增加逆函数选择算子。 |
| 常值复合 | 若 `k_A(x)=b` 且 `b in D_f`，则 `f∘k_A` 等于同域上值为 `f(b)` 的常函数。 | 应用展开和外延性；若要进一步断言值域为 `{f(b)}`，还必须有 `A` 非空。 |

对于左消去，数学上只需 `f` 在两个内层像集的并集上单射；第一版可先使用已有完整接口上的单射证书，不强迫新增“局部单射”内置谓词。对于右消去，满射必须覆盖 `f1,f2` 的整个共同输入域。

两个应保留的反例（数学说明，非本次运行记录）：

```text
g:{0}→{0,1}, g(0)=0
f:{0,1}→{0}, f(0)=f(1)=0
# f∘g:{0}→{0} 是双射；但 f 不是单射，g 不是满射。

g:{0}→{0,1}, g(0)=0
f1:{0,1}→{0,1}, f1(x)=x
f2:{0,1}→{0,1}, f2(x)=0
# f1∘g=f2∘g，但 f1(1)!=f2(1)；缺少满射不能右消去。

g1,g2:{0}→{0,1}, g1(0)=0, g2(0)=1
f:{0,1}→{0}, f(x)=0
# f∘g1=f∘g2，但 g1!=g2；缺少外层单射不能左消去。
```

不承诺的性质也应有负例：`square∘add1 != add1∘square` 可在输入 2 处分辨；`f∘g=f∘h` 没有单射条件不能左消去；相同输出公式但完整输入域不同的两个函数不能直接相等；空域常函数的值域是空集。连续性、可微性、链式法则及选出的逆函数值仍归各自后续接口，本提案没有增加它们。

### 成立、可显式证明与直接 BT 的区别

推荐核心直接规则保持小而完整：签名/完整域封闭、合法应用展开、结合律、单位律、合同替换和像集包含。原像复合、单满双射、消去、逆映射和常值关系先按上述准确前提建立显式证明验收；它们是复合接口必须能表达并支持验证的后续用例，不代表每一行都要成为新的搜索分支。只有反复出现且存在有界前提匹配的关系才提升为直接 BT。不能为了自动识别“可消去”而无界搜索全局的单射/满射事实。

### 搜索与解释边界

逐层应用展开具有结构下降；结合律和单位律只匹配目标的固定结构。已知事实优先，前提使用现有许可的有界验证，不添加全局规范化或无限互相展开。两边对调使用已有等式对称能力。JSON 中区分构造 WD、应用定义和 BT law，并保存各自实际用到的前提。
