# phrase_book：Litex 数学句型册

[English](phrase_book_en.md)

这本句型册帮助已经懂相应数学的读者，把自然数学语言写成 Litex，并用学过的句型表达新的数学内容。

采用的编排是：**以可组合句型为主线，以“自然数学 → Litex”的对照例子呈现每个句型。** 正文围绕句型如何组合展开，每个句型用自然数学与代码的逐项对照说明。

本文记录这一编排与首批样例。完整条目按下述结构继续扩充。

## 从数学意图找到句型

读者从“我想表达什么”进入，例如“任取一个对象”“如果……那么……”“存在一个……”“定义一个函数”“取一个见证”。先看到最常用的写法，再看它如何与其他句型组合。

学习路径分为两条，使用同一套词汇：

- **陈述数学**：说明对象、条件，以及要表达的结论。
- **证明数学**：给出支持结论的计算、构造、分类或其他论证。

同一句“设 x 是实数”，在引入一个对象和陈述一个全称命题时，承担的工作不同。句型册按上下文解释这个区别，不把中文词机械替换成关键字。

## 每个条目的固定结构

| 内容 | 回答的问题 |
| --- | --- |
| 数学意图 | 我现在要做什么？ |
| 核心句型 | 最常用的写法是什么，各部分放在哪里？ |
| 对照例子 | 这句自然数学具体对应哪些 Litex 代码？ |
| 条件与作用域 | 哪些事实需要先成立，变量在哪里可以使用？ |
| 组合方式 | 它能接到哪些句型里，下一步还能怎样扩展？ |

完整例子包含自身需要的上下文，可以单独运行。使用占位符的句型模板要明确标为模板，与可运行代码分开。每个意思优先教一种推荐写法，兼容拼法放在补充说明中。

## 例一 引入对象，再陈述事实

自然数学：令实数 b = 2，于是 b + 1 = 3。

```litex
have b R = 2
b + 1 = 3
```

| 自然数学 | Litex | 作用 |
| --- | --- | --- |
| 令实数 b = 2 | `have b R = 2` | 引入对象，说明它的范围和值 |
| 于是 b + 1 = 3 | `b + 1 = 3` | 陈述并检查一个事实 |

组合方式：先引入对象，再写关于它的事实。每条被接受的事实可以供后续语句使用。

## 例二 任意对象，加上条件和结论

自然数学：对于每个实数 x，如果 x > 0，那么 x 不为零。

```litex
forall x R:
    x > 0
    =>:
        x != 0
```

| 自然数学 | 对应部分 |
| --- | --- |
| 对于每个实数 x | `forall x R:` |
| 如果 x > 0 | 箭头前的 `x > 0` |
| 那么 x 不为零 | 箭头后的 `x != 0` |

组合方式：`forall` 给出变量的范围，`=>:` 分开前提和结论。没有前提时，直接列出结论。这里的 x 是局部变量，不因此成为外部可用的对象。

## 例三 定义函数，再使用函数

自然数学：定义 square(x) = x²，其中 x 是实数；因此 square(3) = 9。

```litex
have fn square(x R) R = x^2
square(3) = 9
```

| 自然数学 | 对应部分 |
| --- | --- |
| 定义函数 square | `have fn square` |
| 输入 x 是实数 | `(x R)` |
| 输出是实数 | 参数表后的 `R` |
| 函数值为 x² | `= x^2` |
| 在 3 处使用函数 | `square(3)` |

组合方式：定义得到可调用的数学对象，调用表达式可以继续出现在等式、条件或其他定义中。定义必须对声明范围内的输入有意义；例如倒数函数的输入需要排除零。

## 例四 定义性质，再检查实例

自然数学：把“t 大于 2”定义为性质 is_above_two；3 满足这个性质。

```litex
prop is_above_two(t R):
    t > 2
by def $is_above_two(3)
```

| 自然数学 | 对应部分 |
| --- | --- |
| 定义一个性质 | `prop is_above_two(t R):` |
| 性质的条件是 t > 2 | 定义体中的 `t > 2` |
| 按定义检查 3 满足它 | `by def $is_above_two(3)` |

组合方式：`prop` 为条件命名，`$is_above_two(3)` 是该性质的一个实例，可以放入支持这种事实形状的前提或结论中。定义性质本身不会证明所有对象都满足它。

## 例五 把任意、存在和构造组合起来

自然数学：对每个实数 x，都存在实数 y，使 y = x + 1。证明时取 y = x + 1。

```litex
claim:
    ? forall x R:
        exist y R st {y = x + 1}
    witness exist y R st {y = x + 1} from x + 1
```

| 自然数学 | 对应部分 |
| --- | --- |
| 下面证明一个局部结论 | `claim:` |
| 要证明的目标 | `?` 后面的完整事实 |
| 对每个实数 x | `forall x R:` |
| 存在实数 y，满足 y = x + 1 | `exist y R st {y = x + 1}` |
| 取 y = x + 1 | `witness ... from x + 1` |

这里组合了前面熟悉的数学工作：确定变量范围、陈述存在性、给出具体构造。存在命题说明要得到什么，`witness` 给出满足条件的对象。

见证可以依赖当前的 x。把“对每个 x，都有一个 y”改成“有一个 y，对所有 x 都成立”，会改变数学意思。局部证明完成后导出的是目标事实，内部变量不会因此成为全局名字。

## 内容覆盖与扩充

句型册按三个层次组织，读者可以先掌握常用表达，再按需要查阅完整语言。

| 层次 | 内容 | 编排方式 |
| --- | --- | --- |
| 核心句型 | 引入与命名、事实与条件、量词、定义、局部证明、常用证明动作 | 每条使用上述固定结构，给出对照例子和组合关系 |
| 完整语言索引 | 其他构造方式、结构与模板、递归、外延性、复用、模块等 | 将公开构造映射到相应条目，说明条件与边界 |
| 数学词汇 | 数集、集合与函数操作、领域概念、库接口 | 解释数学含义及使用条件，复用已有句型 |

常用核心的大小是教学安排，不能替代完整覆盖检查。完整索引应对照现行[手册的语句目录](Manual.md#statement-dictionary)、[事实形状](Manual.md#factual-statements)、[对象目录](Manual.md#object-dictionary)和[模块说明](Manual.md#project-organization)逐项维护。

组合方式需要符合实际语法。例如，存在式与集合构造式的条件体不能直接包含任意全称量词；需要时用具体 `prop` 命名该条件。条目应在读者遇到这类组合时解释，不让读者误以为所有句型都能任意嵌套。

后续扩充优先补上：提取见证、唯一存在、分类讨论、反证、归纳、集合与函数相等、命名定理及引用，再补齐完整索引。

## 如何判断句型册是否有效

主要目标是降低读者把已知数学写成正确 Litex 的额外成本。检验时使用数学背景合适的新手和未见过的题目，记录首次正确翻译时间、查询次数、修改次数、提示次数与语义错误。

分别检查三件事：读者是否理解核心句型，是否能查到其他语言构造，以及是否能将已学句型组合成新的正确陈述和证明。语义正确需要核对，不能仅凭程序接受。学习时间和正确率应通过实际试验取得；当前样例通过验证不等于已经证明学习效果或所有数学的覆盖。

精确语法参见[手册](Manual.md)，日常操作参见[学习速查表](Litex学习速查表.md)。逐句检查与修改代码时，使用[Agent Guide](AgentGuide.md)中的持续 Session 工作方式。
