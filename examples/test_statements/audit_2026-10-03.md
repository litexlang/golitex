### Fact：有限基数比较的载体证据

```litex
have A set = {1, 2}
have B set = {1}
have fn f(x A) B = 1
trust $surjective(A, B, f)
finite_set_size(B) <= finite_set_size(A)
```

这是保留的原 non-strict 内核控制，trust 属于原测试输入，本轮未添加证明债。
四条 setup 成功，最后比较仍在 WD 失败；对应 surjection Rust 测试仍失败。
第 1／2 类的归属仍暂定，下一步检查 numeric carrier owner。
[原问题记录](bugs/fact/kernel_gate_2026-10-03.md)。

### ByContraStmt：平方形式的随机失败

```litex
by contra:
    ? i != 0
    i * i = -1
    impossible i * i != 0
```

同一当前 release binary 的 20 次 fresh-process strict 执行中，10 次成功、
10 次失败，原观察仍存在。下面的同目标写法 20/20 成功：

```litex
by contra:
    ? i != 0
    impossible i = 0
```

短写法属于第 1 类作者强化；原随机问题仍是第 2 类待定位候选，没有被关闭。
[原问题记录](bugs/by_contra_stmt/atomic_i_nondeterminism_2026-10-03.md)。

### 既有功能／表示边界

```litex
by contra:
    ? forall x {0}:
        exist y {0} st {y = x}
    impossible 0 = 0
```

此目标本次仍明确拒绝。分类反例需要含 universal 条件的 existential，
当前 QF-only payload 容纳不了；这属于需讨论的表示边界。
[ByContraStmt 限制](bugs/by_contra_stmt/limitations.md)。

已枚举排除所有见证后，bare `not exist` 的自动搜索仍失败；显式 by-contra
路径在测试册成功。non-strict `trust have` 的 body 整体 WD 顺序也仍保留当前
限制。旧 setting/example/try/有限集归纳/replacement 等接口的迁移处置以及
全部 helper 等价，仍由原 [Stmt plan](../../plan/迁移的plan/stmt-execution-legacy-parity-audit.md)
记录；本轮没有改语义或把它们算作已完成。
